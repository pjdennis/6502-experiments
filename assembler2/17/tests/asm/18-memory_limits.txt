NAME: macro_nesting_overflow
DESCRIPTION: Macro nesting itself triggers source-stack OOM under small_heap. The chain is paramless and contains no .include, so during the cascade the only thing growing is the source stack -- macro definitions are all set up before invocation (heap stable thereafter), no parameters means no per-invocation hash_add (heap doesn't grow during cascade), no .include means no extra file frames. With small_heap shrinking the heap-vs-source-stack buffer to 384 bytes the cascade exhausts the buffer mid-expansion. The traceback (EXPECT_STDERR) confirms the OOM site is a macro push during a chain of expansions. The exact depth at which the limit hits depends on the input filename's length (it counts toward the input file frame's size). Both runners (Python harness and self-hosted) now feed the assembler the same TR_INPUT_FILE basename, so the cascade reaches a deterministic depth across machines and runners; with that name length the limit hits during the push of B inside macro C (E -> D -> C -> push-B fails).
ARGS: debug small_heap
INPUT:
 1: * = $0200
 2:   .macro A
 3:   NOP
 4:   .endmacro
 5:   .macro B
 6:   A
 7:   .endmacro
 8:   .macro C
 9:   B
10:   .endmacro
11:   .macro D
12:   C
13:   .endmacro
14:   .macro E
15:   D
16:   .endmacro
17:   E
EXPECT_STDERR:
Error 35 in macro C at line 1: Out of memory
  expanded from macro D:1
  expanded from macro E:1
  expanded from {{MAIN_FILE}}:17

NAME: macro_max_name_args_fit_frame
DESCRIPTION: 127-character macro name with 8 parameters still fits in the 1-byte frame_size at offset 0 (well under the 255 cap). MACRO_MAX_ARGS is 64 now; the binding constraint at the upper end is the frame_size byte, not the arg cap. The worst-case (memory-parented) frame is 1 (frame_size) + 127 (name) + 1 (null) + 1 (curr_type) + 1 (prev_type) + 2 (line) + 2 (prev_data, memory parent) + 31 (activation payload: 8 slots + 7-byte scope tail) = 166 bytes. macro_args_above_cap_at_def covers the arg-cap overflow path, and macro_frame_size_overflow covers the frame_size overflow path.

 2:   .macro AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA a0, a1, a2, a3, a4, a5, a6, a7
 3:   LDA #a0
